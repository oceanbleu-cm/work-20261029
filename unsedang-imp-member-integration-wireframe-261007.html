확정 내용

계정 연동을 로그인 방식별로 둘로 나눈다(p09) — 아이디(ID/PW) 로그인은 비밀번호 확인이 필요해 별도 화면(①)으로 이동하고, 소셜 로그인(카카오·네이버·애플·PASS)은 계정 관리 화면 안에서 토글(on/off)로 그 자리에서 바로 연동한다 — 별도 페이지를 만들지 않는다.

  • 토글을 켜면 해당 플랫폼 로그인(OAuth)으로 소유권을 확인하고 즉시 연동 완료 — 결과는 토글 아래 인라인 안내로만 보여주고 별도 결과 화면(②)으로 넘어가지 않는다
  • 토글을 끄면 연동이 해제된다 — 해제 시 포인트·코인 처리(원복 여부)는 PRD에 없는 추가 결정 필요
  • 로그아웃·사업자 고지 정보는 AS-IS 그대로 유지하되, 계정삭제는 메뉴 행이 아니라 화면 하단의 작은 텍스트 링크로 내린다 — 계정 연동이 새로 추가되며 메뉴가 길어진 만큼, 되돌릴 수 없는 동작은 눈에 덜 띄게 둔다

아이디(ID/PW) 로그인 계정을 연동할 때만 이 화면을 쓴다 — 비밀번호 입력으로 소유권을 확인한다(p05, PRD §3-3). 소셜 로그인(카카오·네이버·애플·PASS)은 이 화면을 거치지 않고 0의 계정 관리 화면에서 토글로 바로 연동한다.

확정 내용

포인트·상담 코인은 대표 계정으로 합산되고(p06), 상담내역·구매내역·리뷰는 대표 계정에서 통합 조회된다(p07). 아이디 연동(①)은 별도 화면으로 이동했던 플로우라 결과도 별도 화면으로 보여준다 — 소셜 토글 연동은 0 화면 안에서 인라인 토스트로 끝난다(별도 결과 화면 없음).

  • 합산 결과 화면에 정확한 포인트·코인 수치를 보여줄지, "합산 완료"로만 안내할지는 PRD §5 C-1(이력 레코드 이관 여부)과 함께 추가 결정이 필요하다 — 와이어프레임은 두 값을 보여주는 안으로 그렸다
  • 비금전 이력은 원 계정에 둔 채 조회 화면만 통합하는 방식이다(§5 C-1) — 레코드 자체가 이동하는 것은 아니다

확정 내용

가입 시도 중 휴대폰 인증 단계에서 동일 번호의 기존(대표) 계정이 있으면, 신규 계정을 만들지 않고 안내 후 기존 계정 세션으로 연결한다(p04, PRD §3-2).

  • 경로별로 번호를 확보하는 시점이 달라 이 다이얼로그가 뜨는 가입 단계도 경로마다 다르다 — PASS는 인증 완료 시점, 카카오/네이버/애플은 OAuth 콜백 시점, ID/PW는 번호 입력란 단계(PRD §3-2)
  • "취소" 선택 시 동작(가입 중단 vs 번호 재입력)은 PRD에 명시돼 있지 않다 — 번호 재입력으로 돌아가는 안으로 그렸다

소급 통합은 개별 사전동의를 받지 않고, 시행 전 전체 공지로 고지한다 — 약관 제3조 (변경사항 사전고지로 효력 발생) 방식을 준용한다(p03, PRD §3-1).

  • 노출 위치·형식(팝업/배너/알림 중 무엇)은 PRD에서 "팝업/이메일/알림 등"으로만 열려 있다 — 와이어프레임은 팝업/배너형 공지 1안으로 그렸다
  • 그룹 내 대표 계정은 "마지막 로그인" 계정이다(p02) — 공지 문구에 그 기준을 그대로 반영했다
